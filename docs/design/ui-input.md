# t99 UI 与输入设计（T99 对齐 + 高频输入）

状态：设计稿。来源：需求讨论两轮（缩放网格/死亡显示/节奏相位/目标五模式/输入解耦）。

## 1. 对手小窗（缩放网格）

- 每侧 n×n，`n = clamp(ceil(sqrt(其余玩家数 / 2)), 1, 7)`；奇数左多右少（左 = ceil(其余/2)）。
- 行优先、左先右后；同一网格尺寸内 id→槽位稳定映射；存活数跌破下一档 n 时重排，
  重排时灰框消失。
- 窗内容：上方徽章数，下方玩家 ID（引擎 pid+1，1..99）。
- **框色 = 危险度**（该棋盘堆顶距顶部距离）：白 → 暗黄 → 橙 → 红。
- **死亡显示**：直接灰框 + 冻结死亡瞬间的棋盘 + 灰蒙版 + 名次；常驻至重排。
- 刷新节流：默认 10Hz，可在设置中调至 15/30/60Hz（纯显示物，不影响对局）。
- 实现注：每棋盘合成单纹理而非逐格 sprite；98 席 2 万格无压力。

## 2. 中央区域

- 主棋盘居中；左侧垃圾条两段色（已就绪/延迟中，对应 armed/delayed 队列，异步落盘语义）；
  右侧 Next 6；下方菱形目标指示器（上=随机 下=反攻 左=临近击倒 右=徽章最多）。
- 信息不对称注：小窗信息（他人棋盘/危险度/徽章）仅人类客户端经复制流本地积分可得，
  程序协议 v2 不含——与 T99 原版一致；将来人机同场若需绝对公平，加可选 thumbnail 字段。

## 3. 目标系统（五模式）

- Tab 循环四模式：随机 / 反攻(attackers) / 临近击倒(kos, 堆高代理) / 徽章最多(badges)。
  ——与现有引擎四模式一致，无需改动。
- **第五种：手动指定单个玩家**（副方向键/副摇杆导航小窗，选中框淡蓝）。
  引擎：`TargetMode::Manual(pid)`，模式键解除手动。
  协议 v3：事件增加可选载荷 `{"t_us":0,"k":"target_player","v":17}`；程序席位同样开放。

## 4. 节奏相位（50% / 30% / 10%）

- 相位 = f(存活数 / 初始人数)，死亡为离散事件，判定确定。
- 相位内：重力、ARE、消行等待、垃圾延迟按各自斜率缓升；相位间：一次性跳变。
- 落进 Ruleset 相位表（ADR-009 的推广）；4 人等小局允许配置覆盖阈值（否则相位塌缩）。

## 5. 输入解耦与高频采样（重要）

原则：**输入采集与逻辑节拍解耦**；墙钟只影响"事件被打上什么 t_us"，
从不进入模拟函数——确定性不受影响（回放重放的是录制的 t_us）。

- **采样 ≥240/250Hz（4ms 粒度）**：
  - 键盘：跑不锁帧的渲染循环（关 vsync，拼图类 GPU 负载极低，事件循环节奏即输入节奏），
    或 250Hz raw-input 线程；事件打点用接收时刻 monotonic 时钟。
  - 手柄：gilrs 250Hz 轮询线程，天然独立于渲染。
  - 240Hz 显示器下事件循环节奏已达标；60Hz 显示器靠不锁帧补足。
- **打点**：逻辑帧 N 开始时锚定 monotonic 时刻 t_N；帧内收到的边沿换算
  `t_us = (ts - t_N) × 1e6`，截断 < 16666；press/release 是不同键，同帧共存合法。
- **物理兑现**：引擎本就按 t_us 在帧内连续时间积分（子步 1ms，事件时刻精确），
  DAS 初次移格、旋转、硬降都发生在真实按压时刻——粒度从 16.6ms 提高到 4ms。
- **对称性**：程序席位协议本就支持精确 t_us；人类补齐后两侧输入精度等同。
- **网络**：上行仍按 v3 事件（帧号 + t_us）；客户端预测本地即时应用，服务端权威重放。
