# ruleset v9：阶段、重力与垃圾

本文是 v9 的正式定义。与 v8 的差别集中在四处：阶段不再按“进入阶段后的时间”爬坡，
而按“剩余对局时间”爬坡；重力与垃圾倒计时合并为同一套阶段参数；垃圾改为锁定时刻进场；
时间伤害改为 40% 起算、2% 一档、封顶 11。

## 1. 记号

| 记号 | 含义 |
|---|---|
| P | 剩余玩家比例 = 存活人数 / 开局人数 |
| T | 剩余时间比例 = 剩余 tick / 总 tick |
| g | 自然落体速度，单位“帧/格”，倒数即每帧格数 |
| r | 垃圾倒计时总长，单位帧 |
| d | 消行延迟，仅在消行时生效，单位帧 |
| ARE | 锁定后的固定出生间隔，恒为 6 帧，不随阶段变化 |

所有帧均按 60Hz 计：`1 帧 = TPS / 60`，与引擎实际 tick 率无关。

## 2. 阶段表

| 阶段 | 选择条件 | g | r | d | 过渡窗口 |
|---|---|---|---|---|---|
| 1 | P > 50%，或 T ≥ 75% 强制 | 60 | 270 | 36 | 40%·T |
| 2 | 10% < P ≤ 50% | 30 | 180 | 20 | 20%·T |
| 3 | 0 < P ≤ 10% | 10 | 60 | 10 | 10%·T |
| 4 | 终态，仅作过渡终点 | 1 | 60 | 10 | — |

阶段选择：

```
phase = 1                               若 T ≥ 0.75
      = 1                               若 P > 0.50
      = 2                               若 P > 0.10
      = 3                               其余
```

阶段 4 只在阶段 3 的过渡终点出现，不能由 P 直接选中。

## 3. 过渡

每个阶段在选定后，把 g、r、d 从本阶段值线性推向“下一阶段的一半”。一半在帧域取算术平均：

| 过渡 | 起点 | 终点 | 窗口 |
|---|---|---|---|
| 1 → 2 | 60 / 136 / 33 | 45 / 113 / 25 | 40%·T |
| 2 → 3 | 30 / 90 / 17 | 20 / 60 / 12 | 20%·T |
| 3 → 4 | 10 / 30 / 7 | 1 / 30 / 7 | 10%·T |

- 阶段 1 的窗口固定为 `T = 75% → 35%`，与何时进入阶段 1 无关。
- 阶段 2、3 的窗口从进入该阶段的时刻起算。
- 阶段 3 直接推到阶段 4 的整值，没有“一半”。

### 3.1 40% 交界

时间伤害在 `T = 40%` 开始计算。若此时仍有过渡在跑，目标由“一半”改为“整档”，
并在该窗口剩余时间内完成。三种边界：

| 40% 落在 | 处理 |
|---|---|
| 过渡中间 | 已走到的值作为新起点，剩余窗口内线性到整档 |
| 过渡终点 | 立刻跳到整档，不做线性 |
| 过渡起点 | 整段窗口都以整档为目标 |

## 4. 取整

先在帧域计算，再向下取整。g 必须表示为 1/n 格/帧且 n 为整数，因此以 n 参与插值。
例如阶段 1 过渡到 40% 时 `n = ⌊60 − 15 × 35/40⌋ = 46`，即 1/46 格/帧。
引擎内部把 g 折算为毫格/秒：`g_milli = 60000 / n`。

## 5. 垃圾

### 5.1 生命周期

1. 入队时若队列为空，立即激活；否则保持灰色。
2. 激活时按当时的 P 与 T 取 r，写入该批次的倒计时总长；此后不再变化。
3. 倒计时逐帧递减，与锁定、消行、ARE 无关。
4. 颜色按剩余比例：`剩余 ≥ 50%` 黄，`剩余 < 50%` 红。
5. 倒计时归零后红闪，等待进场。
6. 进场时机：落块锁定且消行结算完毕之后。连击期间不放行，红闪持续。
7. 每次锁定最多放一批。队首进场后，下一批在同一时刻激活，开始自己的倒计时。

灰色批次不参与倒计时。任何在激活期间到来的垃圾都排在队尾并保持灰色。

### 5.3 R 的来源与校准

T99 的三处描述指向同一组数值，只是粒度不同：

| 来源 | 说法 | 解释 |
|---|---|---|
| 英文资料 | 早期约 2.5 s，前 50 名约 1.5 s，前 10 名约 0.5 s | 黄转红的时刻，即总时长的一半 |
| 中文维基 | 黄变红用时 2.5 / 1.5 / 0.5 s | 同上 |
| 规则文档 | 每次垃圾的处理时间 4.5 / 3 / 1 s | 总时长 |

英文资料把 2.5 / 1.5 / 0.5 秒说成“垃圾进入场地前的延迟”，即全程；中文维基把同样的
数字说成黄转红的时刻。两者相差一倍。本规则采用英文口径的全程，并取整数帧以便黄红对半：
136 / 90 / 30 帧（2.27 / 1.5 / 0.5 秒），黄 68 / 45 / 15 帧，红 68 / 45 / 15 帧。

校准参考是 master 的消行速率。本引擎实测 master 为 1.52 行/秒、3.21 块/秒，
因此一个 2.27 秒窗口可消约 3.4 行，约为 12 行待进上限的 28%。窗口再长一倍（270 帧）时
可消 6.8 行，超过上限的一半，稳定消行的程序就能把队列抵消掉大半——这正是旧口径下
「99 人局只出局 28 人、88% 的送达行被上限丢弃」的原因。

### 5.2 与消行的关系

垃圾在消行结算之后进场，因此不会再出现“消行动画期间棋盘上移”的情形。
消 5 行的现象从规则上不可能发生。

## 6. 时间伤害

`T = 40%` 起为 1，每过 `2%·T` 加 1，到 `T = 20%` 累计 11 后不再变化：

```
penalty = 0                                    T > 40%
        = 1 + (elapsed − 0.40·total) / (0.02·total)    20% ≤ T ≤ 40%
        = 11                                   其余
```

作用于实际进入对手队列的垃圾，在等待队列上限截断之前加上；阻挡与抵消不受影响。

## 7. 对局时长

正式对局 99 人为 20 分钟。其余人数沿用原插值，99 人处取 1200 秒。

## 8. 其它

- 软降：1 格/帧。
- 锁定延迟：500 ms，最多 15 次重置。
- 消行延迟 d 只在消行时生效；ARE 恒为 6 帧，每块锁定后都要等。
- 硬降、暂存、预览数、SRS 踢墙不变。

## 9. 伪代码

```
fn pacing(phase, enter_left, left, total) -> (n_g, r, d):
    base = PHASES[phase]
    win  = base.window_pm / 1000 * total
    start = if phase == 0 { 0.75 * total } else { enter_left }
    end   = start - win
    p40   = 0.40 * total
    half  = (base + PHASES[phase+1]) / 2          # 帧域，除阶段 3
    full  = if phase == 2 { PHASES[3] } else { PHASES[phase+1] }

    if left >= start: return base
    if p40 >= start:                              # 窗口起点已在 40% 之后
        return lerp(base, full, (start-left)/win)
    if p40 > end:                                 # 40% 在窗口内部
        if left >= p40:
            return lerp(base, half, (start-left)/win)
        v40 = lerp(base, half, (start-p40)/win)
        return lerp(v40, full, (p40-left)/(p40-end))
    # 窗口在 40% 之前结束
    if left > p40: return lerp(base, half, (start-left)/win)
    return full if end == p40 else half
```

`lerp` 在帧域计算后向下取整；三个阶段字段分别插值。
