# t99 规则决策记录（ADR）

- **ADR-000 首先是游戏**：Arena Module 必须先是一个对人类成立的合理游戏，其次才是评测器。
  游戏的有效性（物理正确、规则可信、平衡、可观赏）是测量有效性的前提——被数十年人类
  对局验证过的技能结构与排序性质是复刻免费继承的资产；对原版的每一处偏离都必须由
  “人类手感保真”或“测量需要”之一辩护，冲突时物理从手感、编排从测量。
  人类游玩本身就是校准仪器（与 Bot 校准矩阵对称）。**状态：立为总纲。**

格式：编号 / 决策 / 状态 / 依据。引擎侧全部数值集中在 `Ruleset`（`t99-core/src/lib.rs`），
公开档与考试档在此分叉。

## 已定（引擎已实现）

- **ADR-001 引擎侧 DAS/ARR**：草稿的离散 tap 按键会让程序免费获得 1格/帧移动而人类受
  DAS 限制，属"移动特化"。改为压放式键 + 引擎统一 DAS(10F)/ARR(2F)，对人类/程序/Bot
  完全一致。Bot 也因此像真人一样需要规划移动时间。**状态：已实现，协议 v2。**
- **ADR-002 全整数物理**：时间 ⅓ns 拍、位置毫格、i128 中间量、随机流派生。跨平台逐位
  重放是回放校验与 Bot 校准的前提。**状态：已实现。**
- **ADR-003 名次排序键**：存活 > 送出 > 消行 > 棋盘高度 > 编号（沿用草稿 rule.md §8）。
  编号偏差由正式评测跨局轮换编号对冲。**状态：已实现。**
- **ADR-004 击杀与徽章**：击倒归属 = 最近一次垃圾进场批次发送者；击倒者获得被击倒者
  **全部徽章并额外 +1**（T99 wiki 确证），档位按徽章枚数 2/6/14/30 → +25/50/75/100%。
  **状态：已按 wiki 实现。**
- **ADR-005 垃圾机制**：按 T99 wiki 重写为三态独立进场：灰（排队）→黄（计时）→红（即将）
  →进场；阶段时长按存活数 ≥50/≥10/其余 → 2500/1500/500ms；**进场与落块无关**；连击进行中
  阻挡进场；消行 1:1 抵消（从队首扣）；队列上限 12；进场推块、完全推出判负；同洞 0.7。
  **状态：已实现（wiki 忠实）。**
- **ADR-006 目标奖励**：被 2/3/4/5/6+ 人瞄准 → 送出 +1/+3/+5/+7/+9（草稿 §5.3）。
  注意 2–4 人小局中"引怪换攻击"权重远大于 99 人局，平衡性待实测。**状态：已实现。**
- **ADR-007 Attackers 模式分裂**：被多人瞄准时垃圾均分（余数给编号最小者），无人瞄准
  时退化为随机。T99 实机行为（全量 vs 分裂）未确证。**状态：已实现（均分），待考。**
- **ADR-008 锁定时序 1ms 子步**：物理以 1ms 子步积分，位置累加器精确、锁定判定精度 1ms。
  确定性不受影响（同输入同结果），仅与"纯连续时间"的理论值有 ≤1ms 偏差。
  **状态：接受。**

## 待定（占位值已在引擎中，可调）

- **ADR-009 重力曲线**：现按存活数分档（≥10:800 / ≥7:1200 / ≥5:2000 / ≥4:3000 /
  ≥3:5000 / ≥1:8000 毫格/秒，上限未到 1G）。T99 实机曲线需社区实测拟合；是否叠加
  时间维度加速待定。
- **ADR-010 预览数量**：现为 6（草稿值）；T99 截图似为 5。改一个常量即可。
- **ADR-011 ARE/消行延迟**：已实现：相位化 Clear/Are 状态机（ARE 基准 100ms=准则 6F；Clear 300→150ms），Bot 吞吐压至人类区间；消除闪烁动画已入客户端（快照 clearing 行）。
- **ADR-012 180° 旋转**：协议保留 `flip` 键，ruleset `allow_rot180=false`（T99 无 180°）。
- **ADR-013 软降速率**：现 60000 毫格/秒（≈1G）。实机软降手感需实测校准。
- **ADR-014 DAS/ARR 实测值**：现 10F/2F（Switch guideline 常见默认）。T99 不可设置，
  应有固定值，待实机测量。
- **ADR-015 对局倒计时与 0 杀加速（替代原「无进展截断」）**：已实现。对局预算按人数
  自动推导（4p=5min → 99p=15min 线性插值，`--time-limit-secs` 可覆盖），随 hello 下发，
  镜像必然一致；快照带 `match_secs_left`/`burn_x10`，客户端常显倒计时。展览机制：
  最后一次击杀 T 秒后（T>60）倒计时以 T/60 倍速燃烧（`--stall-accel`，默认开；
  **正式 Arena 关闭**——难度由相位参数自然上升），击杀复位 1×。归零即**流局**：
  幸存者**仅按徽章数**降序排名（平局按编号），与 rule.md §8 排序键不同，属本服务器的
  展览规则。**配套**：垃圾进场顶起活动块时夹回场内（空中块被顶不判负，仅真挤压判负）；
  出生点移到可见首行。
- **ADR-020 瞄准可视化与反攻策略**：快照带 `targeted_by`（谁在瞄我）。小窗边框
  蓝=被本方瞄准、红=瞄准本方、紫=互瞄；HUD 显示被瞄数。Advanced/Expert 目标策略：
  被瞄→反攻（没有被瞄时反攻无意义），否则常规（Expert 危险时优先反攻、徽章领先
  收割）；Basic 保持随机。
- **ADR-021 观战网格等级**：开局取最小可容网格（2N² ≥ 存活对手数；8 人局 = 2×2，
  99 人局 = 7×7）。此后仅因淘汰降级：存活跌出 K-2 级容量 2(K-2)² → 网格降为 K-1
  （98 人局跌穿 50 → 7×7 变 6×6），恒不低于 2×2。新局（帧号倒退）重置。死者按名次
  升序补位（最近淘汰在前），网格缩小时先移除最早淘汰者。
- **ADR-022 判定弹出与相位爬坡**：引擎记录最近消行判定（行数/旋转/全消/B2B/帧号，
  快照 `last_clear`），客户端在 1s 窗口内于板上方显示「消N / Tetris / T-Spin X /
  Clear（B2B 前缀）」，COMBO 显示于其下方；新判定直接替换；**普通消 1（无旋转/
  全消/B2B/连击）不弹**。相位参数爬坡：相位内线性上升但封顶在到下一相位阶梯的一半
  （末相位 P4 爬到 1G）。
- **ADR-023 节奏对齐 T99**：重力 P1 基准 750 毫行/秒（准则 L1 ≈0.8s/行；自然流速
  待实机校准），P2/P3/P4 = 1500/3000/6000→1G（近似准则 L5/L15/L20+ 档）；垃圾阶段
  按相位 1200/900/650/450ms（黄红各一段，总排队 2.4→0.9s，T99 满厅约 2.5-3.5s）；
  消行延迟 300/250/200/150ms（≈T99 动画，客户端闪烁窗口即 Clear 相位时长）。垃圾条
  单列堆叠（红下黄中灰上），**红段以黄转红相同间隔闪烁（T99 红闪块）**。小窗边框
  拆分：淡蓝/红/紫=瞄准关系边缘线（1.5× 粗），白/黄/橙/灰=危险度背景。主界面分区
  对齐规格：保存/对战盘/预览上沿取齐（+270），垃圾下沿对齐对战盘下沿（-270），攻击
  盘在下留 16px 空隙；侧栏网格外缘由 `side_center_x` 钉在窗口内缘 -12px（曾因固定
  SIDE_X 在 49 人局把部分对手渲染到窗口外）。
- **ADR-024 观战补史**：服务器缓存当前局全部 tick；观战端中途加入时 game_loop
  单线程回放 hello+全部历史后再激活直播（时序保证，镜像确定性不破）。对局间隙加入
  直接激活，由下一局 hello 覆盖。客户端镜像为有状态确定性引擎，回放是唯一无损追赶
  方式，追平速度即网络速度。
- **ADR-016 隐藏档 Bot**：master/grandmaster 已实现为**外部程序**（见 ADR-026）。
  公开档（basic/advanced）源码对参赛模型开放；expert 源码不开放；M/GM 整目录
  `crates/t99-bot-m` 在 Arena 公开包中剔除，参赛方仅知晓其存在。
- **ADR-017 目标五模式**：Tab 循环 随机/反攻/临近击倒/徽章最多（现引擎四模式不变）；
  新增第五种手动指定 `target_player(pid)`，副方向键导航小窗选择。协议 v3 事件需支持
  可选载荷。**状态：已实现（协议 v3）。**
- **ADR-018 节奏相位**：按存活比例 50%/30%/10% 切相位；相位内参数（重力/ARE/消行等待/
  垃圾延迟）各自缓升，相位间跳变。是 ADR-009 的推广，进 Ruleset 相位表；小局可覆盖
  阈值。**状态：已实现（相位表 + Clear/Are 状态机）。**
- **ADR-019 高频输入打点**：输入采集与 60Hz 逻辑解耦，≥240/250Hz 采样，事件按接收
  时刻换算帧内 t_us（引擎按精确时刻积分）。墙钟不进模拟函数，确定性不变；程序席位
  本就支持精确 t_us，人类侧补齐后输入精度对等。**状态：已实现（客户端打点 + 不锁帧渲染循环）。**

- **ADR-025 外部程序席位**：参赛模型提交的程序与内建 bot 同席不同源——服务器以
  `SubprocessAdapter`（stdin/stdout 单行 JSON，16ms 帧预算，ready 2s 握手）驱动之。
  `--bots` 席位语法扩展为 `tier`（内建）或 `ext:label=path`（外部可执行）。生命周期：
  开局 `setup(hello)`、逐帧 `act(snapshot)`、结算 `finish(result)`（2s 宽限后击杀）；
  程序死亡或连续 miss 超 600 帧 → `engine.kill(pid, "program_dead")`（与正式 Arena
  的宿主判负一致）。服务器/analyze/duel 三处同语法。已知限制：外部席位逐帧串行
  等待应答，外部程序过多时会侵蚀 16ms 帧预算（后续可并行化 per-seat 线程）。
- **ADR-026 隐藏档 M/GM（外部程序）**：`crates/t99-bot-m`（Arena 包剔除）出两个
  二进制 `t99-bot-master` / `t99-bot-gm`，只依赖 serde 线协议——不依赖 t99-core/
  t99-proto，反向验证参赛接口自洽。定位谱系（2026-10-27 定稿）：
  - null 送人头；basic = Tetris 基线（随机目标）；advanced = 有攻防的对局基线；
  - expert 严格强于 advanced（源码不公开）；
  - master 严格远强于 expert：2 层束搜索（当前块+下一块、Hold 分支）、el-Tetris
    特征 + 攻击/抵消/B2B 期望收益、被瞄反攻、危险切生存权重；
  - grandmaster = 激进的 master：「可以不活，其余参赛者必须死」——连击/T-Spin/
    B2B/全清全都要发出去尽可能多的行，徽章≥2 且攻势成型即转收割；危险阈值更高
    （16 行 vs M 的 13 行），极限兜底权重不弱于且严格强于 master，但触发更晚——
    实际上未必能活，火力分摊依赖其他 GM/M。
  - 关键实现：(1) (x,rot) 状态 BFS 执行器，精确复刻引擎平移/踢墙转移，逐帧从实时
    状态走目标态，不可达候选拉黑重规划（曾因「平移+旋转」执行模型到不了负 x/踢墙
    位而系统性错锁，行/块仅 0.22；修复后 0.40）；(2) T-Spin 踢墙进槽候选（贴地
    枚举 SRS 踢墙终位 + 三角判定），执行为「BFS 到前置态→软降贴地→旋转→硬降」；
    (3) 引擎修复：HardDrop 不再清 `last_rot_kick`——旋转→硬降成立 T-Spin（T99
    语义，此前旋转后硬降永不成立自旋）；(4) 协议 v6：Frame 增 `targeted_by` /
    `time_secs_left` / `burn_x10`（反攻决策与终局感知），兼容缺省。
  - ~~校准：5 档 16 局混战平均名次 gm 1.00 < m 2.00 …~~ **勘误（2026-10-28）**：上 early
    校准以「时限流局名次」为主指标，而强手互打常 0 击杀全员撑满时限，此时流局
    tie-break（徽章全 0 → pid 升序）使名次≈座位序伪影（lab/combo 代理实验证实）。
    可靠指标改为：送出量 / solo 存活 / KO-徽章（真实击杀场）。
  - **选秀锦标赛（ADR-026.1，2026-10-28）**：5 个子代理在 `lab/` 独立沙盒各造一族
    攻击策略 bot（B2B 井型 / T-Spin 特化 / 连击链 / 态势自适应状态机 / KO 猎杀极限
    激进），统一口径 murder-ball 锦标赛（10-11 人场 + 1v1 火力差哨兵）定座次：
    **well（B2B Tetris 井型工业）火力断档**——A 场送出 222/局，1v1 对旧 M +123、
    对旧 GM +117（双旧档输出腰斩），solo 4/4 满时；berserk v7（attack 20/危险阈值
    20/垃圾容忍 16，徽章≥1 即收割）1v1 双正差、10 人实杀场送出 1.4-2× 于旧 GM；
    adaptive（五态状态机）是唯一有真实击杀的候选（KO 0.09/局、FFA 零死亡）；
    tspin 火力被压制淘汰；combo 结构性封顶（连击深度 2-3，不推荐）。
    **移植定案：master ← well（工业压制，稳健）、grandmaster ← berserk v7（极限
    激进 + GM 强兜底）**，adaptive 留 lab 作第三隐藏档备选。移植经位级等价验证
    （官方自打 vs 官方-实验室对打 hash 轨迹一致）。duel 升级：KO/存活率列 +
    每局死亡名单；锦标赛脚本 `lab/tournament.py`。

- **ADR-027 单局服务器与观战健壮性（2026-10-28）**：一台服务器只服务一局——结算展示期后
  驻留现场（保留 history 供晚到观战端补史、保持 WS 连接），不再自动开下一局；客户端断连/
  失步后保持最终画面渲染（镜像不清空）。多局循环与大厅重启以后按需再做。配套修复：
  ① 客户端镜像 tick 序号连续性校验（重复/缺帧 → 判失步，观战端自动重连补史自愈，
  玩家端保持最终画面）——曾因 release 客户端二进制落后于引擎语义（HardDrop 保留旋转
  标记）导致镜像与权威分叉，表现为对手小窗存活数崩坏、网格假性缩并、假名次；
  ② rebuild_thumbs 实体清理由漏掉 mask 导致网格重拟合后旧蒙版残留错位；
  ③ 侧栏网格定位 side_center_x 改按实际窗口半宽自适应（原硬编码 800 假定 1600 宽）。
